Two agents in the same conversation

Not two isolated sessions passing summaries back and forth. Claude Code and Codex work inside one supervised desktop application, with the shared history and project state kept visible between them.

You stay in the middle

Talk to both agents at once, click into either panel to address one directly, or lock targeting with a right click. When one agent responds, the other receives that contribution as context on its next round—not as an instruction it must blindly follow.

Because the agents are trained differently, they investigate differently. The point is not duplicate output. It is a Lead with a real Reviewer, two independent readings of the same problem, and a Director who decides what happens next.

  • Separate Claude Code and Codex work panels.
  • A shared center surface for objectives, stage documents, and history.
  • Human or AI Director control over each round.
  • Share Responses, Reach Consensus, and Review actions built into the workspace.

As light—or as structured—as the work requires

A one-line correction should not need ceremony. A consequential build should not depend on one fragile prompt stream. ConflabCode supports both ends of that range.

Flexible workflow

Quick fixes, freeform objectives, or a governed build

Ask a Lead to move a button and let it work immediately, with review one click away. Give ConflabCode a handful of loose objectives and let Freeform carry them through design review, implementation, and verification. Or use the full staged workflow when every decision needs a visible record.

Automatic continuity

Context that manages itself

Set context thresholds by model. When an agent reaches one, ConflabCode prepares a fresh instance and transfers the working history so the project continues without manual context bookkeeping.

Intent, preserved

Every stage checks the original goal

Brainstorm notes feed Design, Design feeds Implementation, and Verification checks the resulting work. Review is anchored to what you asked for, not merely the last agent's description.

One click

Reach consensus without averaging away disagreement

Orient both agents on the same question, let each catch what the other missed, and consolidate their findings into one opinion you can act on.

More work, fewer retries

Ten instances and a safer tool layer

Run up to ten ConflabCode instances at once. Built-in tools also catch common quoting, path, and edit failures and retry them before they consume another full provider round trip.

Behavior Policy and Rules you control

A visible workflow from idea to verification

Structured work moves through four connected stages. Each stage has its own document, its own Lead and Reviewer assignments, and a clear relationship to the work that came before it.

01

Brainstorm

Explore the problem conversationally, then capture the notes that should survive into the design.

02

Design

Turn those notes into explicit design items and keep unresolved questions visible instead of guessing.

03

Implementation

Import the accepted design, build in traceable slices, and let the Reviewer pressure-test the result.

04

Verification

Check the implementation against the approved intent, surface failures, and preserve the final evidence.

The structure stays under your control

Continuity, provenance, and agent behavior are visible parts of the product—not hidden assumptions. The highlighted regions below are taken directly from the application.

Context that manages itself

Choose the threshold. Stop watching the gauge.

Large model windows can become expensive and unfocused before they become full. Smaller windows need more runway. ConflabCode lets you set the handoff threshold by context size, then manages the transition when work reaches it.

Provenance that survives handoffs

Follow a decision back to where it started.

Design items retain their Brainstorm source. Implementation items retain their Design source. Verification can follow the chain instead of trusting a handoff summary, and later changes remain visible without silently erasing earlier approval.

Behavior Policy and Rules

Define how the agents work with you.

Behavior Policy describes the Lead, Reviewer, and Director responsibilities for each stage. Rules capture your global working preferences and project-specific expectations. A full reset restores the shipped defaults whenever you need it.
